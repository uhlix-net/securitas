Securitas agent for Linux

Compliance checks on Linux hosts run through the Securitas agent: a small RPM (securitas-agent) with the compliance wrapper, Goss and a setup command. It creates the scan account {{ scan_user }} (password locked), authorizes Securitas's SSH key and adds one sudo rule: the account may run only /usr/local/sbin/securitas-cis-audit as root. At scan time Securitas copies the benchmark's audit content to the host; the wrapper runs it as root in a temporary root-only folder and deletes it. Nothing runs on the host between scans.

Trust: whoever controls Securitas decides what the checks run as root on these hosts, as with Semaphore or a credentialed Tenable scan. Keep Securitas's admin accounts and its SSH key protected accordingly.

Install

{% if not pubkey %}

Securitas has no SSH key yet. Set the Linux scan account and key under Scan credentials first: the installer authorizes that key on each host.

{% endif %} {% if not rpm %}

This Securitas image has no agent RPM, so the installer cannot download it. Use the RPM from the GitHub release instead.

{% endif %}

On each Rocky Linux / RHEL / AlmaLinux 8 or 9 host (x86_64), as root:

curl -fsS {{ base }}/agent/install.sh | sudo bash

If the host does not trust Securitas's certificate yet (a private CA), give curl the CA file: curl -fsS --cacert /path/ca.pem {{ base }}/agent/install.sh | sudo SECURITAS_CA=/path/ca.pem bash. To read the script first: install.sh.

Then add the host as a Linux target under Targets, run a vulnerability scan once (so its OS is known) and a compliance scan.

By hand or with Ansible

dnf install {{ base }}/agent/securitas-agent.rpm      # or the RPM from the GitHub release
securitas-agent-setup --user {{ scan_user }} --key '{{ pubkey or "" }}'{% if allowed %} --from {{ allowed }}{% endif %}

Remove: dnf remove securitas-agent (removes the sudo rule; the account is kept) or securitas-agent-setup --remove (removes the sudo rule and Securitas's key).{% if rpm %} RPM in this image: {{ rpm }}.{% endif %}

Allowed source addresses

The installer limits Securitas's key to these addresses (from= in authorized_keys): the addresses Securitas's scans come from, such as your Kubernetes nodes. Empty: any address. Changing this affects hosts installed afterwards; re-run the installer on existing hosts to update them.
